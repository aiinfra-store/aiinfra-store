# 03 · 训练营阶段一：大模型推理部署、引擎调优与性能优化实战

> **这是公开的简版大纲**：列出全部模块和每一讲的标题。每一讲的详细要点、讲义和实验代码，报名后在课程仓库里看。

> AI Infra 学院 · **训练营**（共两个阶段）。这条线讲的是**怎么把大模型服务交付出去并且跑稳**，和讲原理的特训课、讲深度方向的专精课是并列的两类课。

**这是训练营的起点，也是整条线里最该先学的一阶段。** 学完你能独立把企业的第一批大模型服务交付上线——从挑卡开始，到服务挂在统一入口上、有监控有告警为止。

## 阶段基本信息
* **先修**：没有前置要求。会用 Linux 和 Docker 就能跟。想先把硬件原理打透的，可以配合 [01 特训课 · 硬件、存储与网络](01-hardware-storage-network.md)。
* **课时**：35 讲，每集约 40 分钟。**内容多的 5 讲拆成上下两集**（第 06、10、14、22、30 讲，大纲里逐讲标明了上下集各讲什么），全课共 40 集、约 27 小时。
* **一句话介绍**：用一台 8 卡服务器，从硬件选型、引擎内核、参数调优、场景调优到压测评测与成本核算，完整交付企业的第一批大模型服务。
* **学完能投**：大模型推理优化工程师、推理部署工程师、AI 应用运维 / 私有化交付。
* **适用人群**：运维工程师、SRE、后端开发、AI 解决方案架构师。
* **学完交付**：指标基线表与排障决策树、Qwen3.8-27B 与 DeepSeek-V4.1-Flash 部署方案、量化与评测报告（含 Nsight Systems 深度剖析）、四类场景的调优配置与对照数据、服务工程化配置（限流 / 优先级 / 熔断 / 负载均衡）、**每百万 token 成本测算表与调优归因清单**、Embedding / Rerank 服务、New-API 统一入口、监控日志配置模板。
* **版本基线**：vLLM `v0.33.0`（CUDA 13.0 / PyTorch 2.14）/ SGLang `v0.5.23`。**引擎迭代很快，课程承诺随版本同步修订**：讲义里每一处涉及具体版本的地方都标了基线，主干架构变化会重录，参数级变化以更新说明的形式补进对应讲。

## 这门课不教什么

边界说在前面，省得花冤枉钱：

* **不教模型算法、不教训练和微调**——这是推理侧的课。想训模型去 [05 分布式训练](05-distributed-training.md)。
* **不教写 CUDA kernel**——第 09 讲只教**读懂**引擎里的算子（不要求 C++ 功底）。想自己写算子去 [06 算子开发与优化](06-gpu-kernel.md)。
* **不教 K8s 和集群**——这门课全程在一台机器上。服务多到单机管不过来之后的事，在 [04 训练营阶段二](04-k8s-cluster.md)。
* **不教多模态模型的部署**——语音、视觉、图像视频生成是[另一门选修](onhold-multimodal.md)（暂无排期）。
* **不教 RAG 和 Agent 应用怎么写**——只教服务侧怎么把它们支撑好：Embedding / Rerank 怎么部署、Agent 负载怎么调优。

**只教一件事**：把一个已经训好的模型，在给定的机器上部署得又快、又省、又稳，并且说得清快了多少、省了多少。

## 结业项目怎么写进简历

**先说结论：这门课学完能写出一个像样的项目条目，但写法决定它值不值钱。**

学完你手上有的是**数字**——而绝大多数人会把它写成「熟悉 vLLM / SGLang 部署与调优」，**一句话就把最值钱的东西全扔了**。

### 三条翻译规则

**1. 数字优先，技术栈靠后。** 简历筛选时，招聘方扫的是结果不是名词。

| ❌ 常见写法 | ✅ 该怎么写 |
|---|---|
| 熟悉 vLLM / SGLang 部署与参数调优 | 在 8 卡 RTX PRO 6000D 上部署 27B 模型，通过分块预填充预算与批次上限调优，**P99 首字延迟从 2.1s 降到 0.8s，吞吐提升 1.7 倍** |
| 使用 EvalScope 进行压测评测 | 建立 TTFT / TPOT / Goodput 指标基线并做并发梯度压测，**在 P99 < 1s 的 SLO 约束下把有效吞吐（Goodput）从 X 提到 Y** |
| 了解模型量化 | 对 27B 模型做 FP8 量化并用 MMLU-Pro / C-Eval 验证精度，**显存占用降低 42%、评测分数掉 0.6 分，判定可上线** |
| 熟悉 KV Cache 优化 | 通过 System Prompt 排版规范与会话亲和路由，**把 Agent 场景前缀命中率从 31% 提到 78%，每轮成本下降 54%** |
| 搭建了推理服务 | 设计服务层准入与优先级队列、least-pending 负载均衡与三级降级策略，**突发流量下错误率从 12% 降到 0.3%** |

**2. 一条项目经历 = 动作 + 结果 + 代价。** 只写收益不写代价，技术面一问就露。量化省了显存但掉了零点几分、投机解码提了速但高并发下收益反转——**把代价一起写出来，反而证明你真测过**。

**3. 最后一行永远是钱。** 「优化后每百万 output token 成本从 ¥X 降到 ¥Y，按日均 Z 亿 token 计年省约 N 万」——这是第 29 讲那张成本测算表的直接输出，也是**推理优化岗唯一对外说得通的 KPI**。有这一行的简历和没有的，不是一个档次。

### 一条守则：规模如实写

课程实验是**单机 8 卡**级别的。简历上**必须如实写「实验规模 8 卡 / 单节点」**，不要含糊成「大规模部署」。

原因很直接：面试官一定会问「你最大跑过多少卡 / 多大 QPS」。**如实写 8 卡，远好过含糊其辞**——前者是诚实，后者一戳就破，而且破的不只是这一条，是整份简历的可信度。

### 它能帮你过哪一关

**作品不等于工作经历。** HR 筛简历看的是公司和职责，这一点课程改变不了。**作品的战场在技术面**——它让你在被问深时有东西可讲、可打开、可复现。

被追问时你应该能当场答出来的（课程里都练过）：
* 「这个数字怎么测的」→ 压测方法、并发梯度、预热与稳态怎么区分（第 26、28 讲）
* 「为什么这么调」→ 指标基线和取舍曲线（第 08、24 讲）
* 「线上突然变慢你怎么查」→ 排障决策树，从哪个指标开始缩范围（第 10 讲）
* 「这套方案的成本是多少」→ 成本测算表，换机型换模型当场重算（第 29 讲）

**更现实的一句话**：靠作品进面，中小公司和创业公司远比大厂社招好走；大厂社招基本还是看现司职级和项目盘子。这门课能帮你够得着前者。

## 实验环境与成本

**门槛比想象的低，大部分内容不用多卡机。**

| 模块 | 环境 | 说明 |
|---|---|---|
| 模块一（算力选型与硬件匹配） | 零硬件 | 规格对照、算账、选型推演，一台笔记本就行 |
| 模块二（推理引擎内核架构） | 零硬件到单卡 | 源码剖析与架构讲解为主；想动手验证的，单卡即可 |
| 模块三（指标体系、读算子与排障） | 零硬件到单卡 | 指标推导与排障决策树零硬件；Nsight 时间线分析单卡即可 |
| 模块四（启动参数与极限调优） | 单卡起步，多卡更完整 | 大部分参数在单卡上就能看出效果；多模型混部与张量并行那几讲需要多卡 |
| 模块五（容器化与标杆模型交付） | 单卡 | 镜像、容器运行时、模型加载，单卡够用 |
| 模块六（KV 复用与四类场景调优） | 单卡起步 | 前缀缓存、CPU KV 卸载、长上下文、延迟与吞吐取舍，单卡都能测出曲线 |
| 模块七（压测评测、成本核算与统一入口） | 单卡或普通云主机 | EvalScope、成本测算、Nginx、New-API 这部分不吃显卡 |
| 模块八（监控大盘、日志与通关验收） | 单卡或普通云主机 | Prometheus / Grafana / 日志审计不吃显卡 |
| 阶段通关项目 | 一台多卡机，集中用几小时 | 按量租用即可，用完即停 |

讲师演示用的是企业 **8 卡 RTX PRO 6000D / 4 卡 RTX PRO 6000** 生产机型，但**不要求学员自备同规格机器**——课程会标明每个实验的最低配置，以及哪些可以降规格复现。
