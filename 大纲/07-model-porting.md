# 07 · 专精课 · 模型适配（35 讲）

> **这是公开的简版大纲**：列出全部模块和每一讲的标题。每一讲的详细要点、讲义和实验代码，报名后在课程仓库里看。

> 状态：大纲 v2 2026-11-10（逐讲）
> 对应岗位：模型迁移适配工程师、芯片生态工程师
> 先修：《算子开发与优化》（适配的核心工作就是补算子）；或有扎实的推理 / 训练基础。其余前置知识第 01 讲会速览

## 这个方向在做什么

国产芯片厂要给每个新发布的模型做适配：热门开源模型发布当天就要在自家卡上跑起来，主流推理框架也要移植到自家后端。这类工作在国产化推进下需求持续增长，岗位集中在芯片厂及其生态伙伴、以及有国产化要求的政企项目。

## 这门课不教什么

不教算子怎么写（那是《算子开发与优化》，这门课只教**什么时候该补算子、补完怎么验**）、不教通信库内部机制（那是《集合通信》）、不教模型算法。**只教迁移这件事**：把一个在 NVIDIA 上跑得好的东西，搬到另一套硬件上，并且交得了差。

## 学完能做什么

1. 把一个新发布的开源模型迁到国产卡上跑起来，精度和性能都交得了差。
2. 遇到缺失算子能自己补，遇到精度对不上能逐层定位到第一个发散的算子。
3. 把主流推理框架移植到一个新后端上，而不只是用别人移植好的。
4. 把量化方案和多模态模型也适配下来，并把结果打成镜像部署成真能上线的服务。
5. 给「三个月适配五个模型」这类需求排出带风险项的计划，知道哪几项必须先做技术预研才能估工时。
6. 说清国产软件栈和 CUDA 生态的对应关系与真实差距，不吹也不贬。

## 课程主线

**跑起来 → 算得对 → 跑得快 → 跑得久。**

这四步对应模块二到模块六。**最难的不是第一步**——让模型吐出字来往往一两天就行；难的是让它吐得和 NVIDIA 上一模一样（模块三），以及让它在下个版本的模型发布时还能继续跑（模块六）。

## 模块一：国产算力栈全景（第 01～04 讲）

> **这个模块结束**：你清楚适配工程师每天在解决什么问题、国产 NPU 的硬件和 GPU 差在哪、各家软件栈长什么样，并且手上有一份**自己实测出来的支持矩阵**——哪一格是「能跑」、哪一格是「能跑但慢」、哪一格是「跑不了」，而不是照抄官方文档的「声称支持」。
>
> **本模块交付**：`support-matrix/` —— 一份**自己实测出来的**支持矩阵：模型 × 国产栈，每一格标「能跑 / 能跑但慢 / 跑不了」，而不是照抄官方的「声称支持」；外加一组微基准（矩阵乘、向量运算、访存带宽）与 NVIDIA 卡的对照数据，和一份适配检查清单

## 模块三：精度对齐（第 12～17 讲）

> **这是这门课最核心、也是这个岗位最值钱的一个模块。** 跑起来容易，算得对难。
>
> **这个模块结束**：先把两边弄成真的可比（随机性全锁死），再逐层比对定位到是哪个算子、哪种累加顺序还是量化造成的偏差，并定出一套可验收的精度标准。十个真实案例的定位过程走一遍下来，这类问题你就有套路了。
>
> **本模块交付**：`precision/` —— 逐层比对工具与随机性锁死脚本（先不锁看波动多大，锁死后验证波动消失）、一份精度验收标准与执行后的验收报告、三个注入 bug 的限时定位记录

这门课不是「35 讲听完再做一个大作业」。**每个模块结束你手上都多一个能单独拿出去的东西**，最后的结业项目是把它们装成一个仓库，而不是从零开始写：

## 结业项目怎么写进简历

**这门课的结业作品里有全部课程中唯一带第三方背书的一项：给上游提的 PR。** 链接、评审意见、合并记录都公开可查，把它放在项目条目的第一行。

**项目名这样写**：`大模型国产算力适配：算子补齐、精度对齐与性能调优（平台：〔昇腾 910B 等〕）`

| ❌ 常见写法 | ✅ 该怎么写 |
|---|---|
| 熟悉昇腾软件栈 | 把〔模型〕迁到〔平台〕，**补齐 N 个缺失算子（每个都带单测），端到端跑通** |
| 做过精度对齐 | 逐层比对定位到 N 处精度偏差，**最终输出与 GPU 基线的差异控制在 X 以内，评测分数相差 Y** |
| 做过性能调优 | **把性能从 GPU 基线的 X% 调到 Y%**，并把剩余差距归因到〔a、b、c〕三项 |
| 参与过开源 | 给〔上游项目〕提交 PR #N（附链接），〔修复 / 新增〕了〔具体内容〕，**已合并 / 评审中** |

> **X、Y、〔〕里的内容填你自己实测出来的数和实际用的环境**，上面是写法不是模板。三条规矩和训练营阶段一的同名一节相同：数字优先、技术栈靠后；一条经历写清动作、结果和**代价**；规模如实写。

**规模如实写**：写明平台型号、软件栈版本和对比的 GPU 基线。PR 没被合并也可以写，如实标「评审中」或「已关闭」并说明原因。

**技术面被追问时，你应该当场答得出来的**（课程里都练过）：

* 「精度对不上你怎么查」→ 逐层二分的定位流程（模块三）
* 「为什么国产卡上慢」→ 差距归因表（模块四）
* 「这个算子为什么要这样实现」→ 自补算子的单测和设计说明

## 实验环境与成本

| 阶段 | 最低要求 | 说明 |
|---|---|---|
| 模块一～二（硬件、环境、迁移） | 单卡国产实例 | 各家云上有按量实例 |
| 模块三（精度对齐） | 单卡国产实例 + 一张 NVIDIA 卡 | **需要两边对照**，这是本模块的硬要求；dump 之后的离线比对可以在 CPU 上做 |
| 模块四（性能调优） | 单卡国产实例；第 22 讲需多机 | 通信实验建议集中安排 |
| 模块五（推理适配） | 单卡国产实例 | 第 25 讲的代码阅读部分不需要硬件 |
| 模块六（训练适配） | 多卡国产实例 | 多卡实验建议集中安排 |
| 结业项目 | 单卡国产实例 + 一张 NVIDIA 卡 | 集中使用若干小时 |

**这门课的特殊之处是需要两种硬件**：国产卡用来跑，NVIDIA 卡用来当基准。没有基准就没法做精度对齐，这是绕不过去的。课程会提供机型对照、申请方式与预估费用，以及一批**预先生成的 NVIDIA 侧参考数据**，让没有 N 卡的学员也能完成大部分精度实验。
