# 10 · 高阶课 · AI Infra 架构师（35 讲）

> **这是公开的简版大纲**：列出全部模块和每一讲的标题。每一讲的详细要点、讲义和实验代码，报名后在课程仓库里看。

> 状态：大纲 v2 2026-11-10（逐讲）
> 面向：学完至少一门专精课、有实际工程经验的学员
> 定位：**架构师是职级，不是方向**。这门课不教新的技术栈，教怎么在真实约束下做选择、怎么把选择讲清楚

## 这门课不教什么

不教任何新的技术栈——需要的技术全在前面十门课里。**只教三件事**：怎么把模糊需求问成明确约束、怎么用算账代替拍板、怎么把方案讲到别人肯批。

这门课面向已经能独立干活、但希望把「为什么这么选」讲清楚的工程师。如果你现在更需要补技术栈，先学专精课，学完再回来。

## 学完能做什么

1. 拿到一个需求（多少模型、多少并发、多少预算），能出一套可执行的架构方案，并说清每个选择的理由和代价。
2. 做容量规划和成本精算，向老板和业务方解释钱花在哪、为什么值。
3. 把合规要求逐条翻译成技术措施，给一个跑着的旧系统规划出可回退的演进路线，并把一次大故障复盘到机制层面。
4. 读得懂别人的架构：拆解公开披露的大规模推理系统与万卡集群，用它们的真实数字校正自己方案里偏乐观的假设。
5. 从容应对系统设计面试：不是背答案，而是有一套可复用的推导方法。

## 课程主线

**每一讲都是一个真实场景：给你约束，你出方案，再对着讲评看自己差在哪。**

这门课没有「实验」，只有**场景作业**——因为架构师的产出是决策和文档，不是代码。每一讲都会给出这个场景的参考方案与评判要点，你先自己出方案，再对着参考方案找差距；提交的方案会进入每周的集中答疑视频，挑出有代表性的逐份讲评。35 讲下来会积累 30 多份方案，最后一讲做完整的结业方案与自述答辩。

> **这门课的硬性要求**：方案里每一个数字都要能追溯到一个公式或一次实测。**说不出来处的数字，一律不算。**

## 方案集清单：35 讲攒出一本什么

这门课不是「35 讲听完再写一份大方案」。**每个模块结束你手上都多一份能单独拿出去的文档**，最后的结业方案是把它们收口，而不是从白纸开始：

| 模块 | 这个模块结束时，作品集里多了什么 |
|---|---|
| 模块一：架构方法论 | 提问清单 + 约束表 + 两份容量测算 + 架构文档 |
| 模块二：推理平台架构 | 推理平台方案包（分层 / PD / 降本 / 多租户 / 治理） |
| 模块三：训练集群架构 | 训练集群方案包（网络 / 存储 / 采购 / 治理 / 稳定性 / 验收） |
| 模块四：选型与成本 | 选型与成本方案包（TCO / 自建云混合 / 验收条款 / 国产化） |
| 模块五：安全、组织与演进 | 合规对照表 + 演进路线 + 故障复盘 + 团队方案 |
| 模块六：案例研读 | 两份案例拆解 + 用真实数字校正过的假设 |
| 模块七：推动、面试与收尾 | 结业方案 + ADR + 汇报稿 + 自述答辩 |

35 讲下来不是 35 份听课笔记，而是**一本能摊在桌上给人看的方案集**——面试或内部评审时，你翻的是这本东西，不是回忆。

## 实验环境与成本

**不需要 GPU。** 这门课的产出是方案文档、容量测算表和成本模型，手上有一台能跑表格和画图的机器就够。

真实集群的性能与故障数据由课程提供脱敏样本，用于支撑测算；学员如果手上有自己公司的数据，也可以在脱敏后用于作业，这样收获最大。

## 形式说明

- **视频课形式**：每讲配参考方案与评判要点，你的方案可以提交进每周的集中答疑视频里讲评；学员群内也可以互相评方案，评别人的取舍和自己写一份一样长见识
- **每讲都有场景作业**，作业是这门课的主体，建议跟着做
- 先修建议：**至少学完训练营阶段二（04）或一门专精课（05～09），并且有实际工程经验**。有真实项目背景的学员收获会明显更大，因为作业评的是取舍而不是知识点
