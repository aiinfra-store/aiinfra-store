# 09 · 专精课 · AI 编译器（35 讲）

> **这是公开的简版大纲**：列出全部模块和每一讲的标题。每一讲的详细要点、讲义和实验代码，报名后在课程仓库里看。

> 状态：大纲 v2 2026-11-10（逐讲）
> 对应岗位：AI 编译器工程师
> 先修：《算子开发与优化》（编译器最终要生成算子，不懂算子优化就看不懂编译器在优化什么）
>
> **编程门槛**：这门课不教 C++，默认你能读写现代 C++——模板、RAII、智能指针、CMake 构建。有编译原理基础更好，没有的话课程会补最小必需的概念

## 岗位现状

主要在芯片厂和大厂招，岗位数量少但门槛高。常见要求是 C++ 与 Python 都熟，有 MLIR 或 TVM 的实际经验，了解 LLVM 项目；有 MLIR 代码贡献是明显加分项。

## 这门课不教什么

不教编译原理的词法语法分析（AI 编译器的输入是图，不是源码文本）、不教手写算子（那是《算子开发与优化》）、不教模型结构。**只教张量程序的编译**：一个模型从 Python 代码到硬件指令，中间那几层怎么做。

## 学完能做什么

1. 读懂主流 AI 编译器的工作流程，知道一个模型从 Python 代码到 GPU 指令中间经历了什么。
2. 写图优化 Pass 和自定义 Dialect，做算子融合，并**给一个新硬件写出最小可用的后端**——这是这个方向最核心、国产芯片团队最缺人的那项工作。
3. 用 `torch.compile` 排查和解决实际工程中的编译问题（这是最常用到的那部分）。
4. 说清多卡场景下编译器怎么自动切图、怎么插通信、怎么把通信和计算在编译期重叠起来。
5. 面试时能讲清 graph break 为什么发生、融合的合法性怎么判断、MLIR 为什么要分多层 IR。

## 课程主线

**从「用好现成的编译器」→「看懂它的每一层」→「自己往里加一层」。**

前十讲是任何 Infra 工程师都该会的 `torch.compile` 实战；中间十四讲是编译器的通用原理和 MLIR；最后十一讲是路线对照、分布式编译、代码生成与推理专用编译。**中途退出也不白学**——前两个模块本身就是可直接用上的工程技能。

## 结业项目怎么写进简历

**编译器方向的招聘最明确看的就是「你自己做过一条编译路线没有」。** 这门课的结业作品正好是这一项。先说实话：这个方向对学历和编译背景的要求普遍偏高，作品能帮你过技术面，过不了学历筛选。

**项目名这样写**：`AI 编译路线实现：图优化、自定义 Dialect 与代码生成（路线：〔Inductor / MLIR〕）`

| ❌ 常见写法 | ✅ 该怎么写 |
|---|---|
| 熟悉 torch.compile | 用 torch.compile 加速〔模型〕，**端到端加速 X 倍，并给出归因：算子融合贡献 a、去掉 Python 开销贡献 b** |
| 了解 MLIR | 实现自定义 Dialect（N 个 Op）及到〔目标〕的 lowering，**端到端跑通〔模型的某个子图〕** |
| 做过图优化 | 实现 N 个图优化 pass，**在〔模型〕上把算子数减少 X%、推理耗时下降 Y%** |
| 了解代码生成 | 读通 Triton 从 Python 到 PTX 的流程，**能解释生成的代码为什么比手写慢 X%** |

> **X、Y、〔〕里的内容填你自己实测出来的数和实际用的环境**，上面是写法不是模板。三条规矩和训练营阶段一的同名一节相同：数字优先、技术栈靠后；一条经历写清动作、结果和**代价**；规模如实写。

**规模如实写**：写明你走的是哪条路线、覆盖了模型的哪一部分。只跑通一个子图就写子图，不要写成「支持某某模型」。

**技术面被追问时，你应该当场答得出来的**（课程里都练过）：

* 「这次加速来自哪」→ 加速比归因（结业项目）
* 「为什么要多层 IR」→ 模块四
* 「你的 pass 在什么情况下不能用」→ 图优化的适用条件（模块三）
